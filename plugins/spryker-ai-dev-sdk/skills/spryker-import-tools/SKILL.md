# spryker-import-tools

Two self-contained PHP scripts under `scripts/`, both concept-free (they know nothing about stores/locales/currencies — **you** decide what to do; they do it correctly and print JSON):
- **`csv.php`** — RFC-4180 CSV manipulation.
- **`validate.php`** — pre-boot consistency checks (its own CSV reader; no dependency on csv.php).

**Why use them instead of shell tools or editing by hand:** Spryker CSVs contain multi-line quoted fields (e.g. `cms_page.csv`), so `cut`/`awk`/`sed` corrupt them; and a single bad import row aborts the whole 30–60 min install, which these checks catch statically in seconds. Bulk work in-context burns tokens — the scripts return a terse verdict instead.

## Run

`php <path>/scripts/csv.php <command> <file> [options]` and `php <path>/scripts/validate.php <check> [options]` (host php, or `docker run --rm -v "$PWD":/app -w /app php:8.3-cli php …` if there's no host php). Both print JSON (`{status, …}`, exit `0`/`1`/`2`); read-type commands take `--plain` for clean lines. **Prefer reading the output / the exit code directly over piping through `python`/`ruby`/`jq`** — it's unnecessary here and prompts; the direct read (or `--quiet` + exit code for validate) is the quieter path.

## Invocation & command discipline (authoritative — the one copy; consumer skills summarize and point here)

These rules keep unattended work quiet (no needless permission prompts) and safe. Every skill that drives these tools follows them.

**Locate the scripts:** `.claude/skills/spryker-import-tools/scripts/csv.php` and `…/scripts/validate.php` (setup install, relative to the project cwd), or `${CLAUDE_PLUGIN_ROOT}/skills/spryker-import-tools/scripts/…` (plugin install); docker `php:8.3-cli` fallback per the Run section if there is no host php.

**Invoke by the literal path from the project cwd — never `cd`, never a shell variable.** `$CSV`/`$VALIDATE` in the consumer skills are shorthand for that literal path — resolve it once *in reasoning* and substitute it inline in every call. A `cd` prefix, an assignment prefix (`CSV=… php …`), or a multi-line assign-then-use all miss the allowlist and prompt on every call.

**One simple command per Bash call — no shell operators.** `cd`, `;`, `|`, `&&`, `||`, `$(…)`, backticks, `for`/`while`, redirects, env-prefixes and multi-line commands can never be allowlisted — they prompt regardless. Instead:
- **One op over many files = one command:** list all files before the flags and add `--in-place` (`set`/`replace`/`scale`/`drop-columns`/`filter`/`delete` all take many files); inspect many with one `columns`/`distinct`/`count <f1> <f2> … --plain`. Never a shell loop.
- **Count with the tool** — `rowCount`/`matchedRows` from the JSON, or `csv count --plain`; never `| grep -c`/`| wc -l`.
- **Explore with the built-in Read / Grep / Glob tools** — never bash `ls`/`find`/`grep`/`cat`/`head`/`sed`, and never bundle inspections with `; echo …`. The built-in tools are not Bash, so they never prompt.
- **Config/YAML edits use the built-in Edit tool** (anchored, format-preserving) — never regenerate a file with `python`/`ruby`/`sed`.
- `rm`/`rm -rf` are allowlisted. Delete only what git can restore, ignored build output, or a file this run created under `data/import`, `config`, `src`, `frontend`, `public` or `tests` (never under `.ai-dev/`); surface every deletion as an explicit step. Anything else stays in place and is listed for the person in the final report, never forced.

**Project files change through Edit/Write or the php tools (`csv.php`, `gate --save`) — never a shell heredoc (`<<'EOF'`), `sed -i`, or a `>` redirect aimed at a path under the project root.** Edit/Write show each change as a reviewable diff and keep the harness's read-before-write check; a file written from Bash skips both. A redirect also truncates its target before the command runs: `php … gate > .ai-dev/gate-baseline.json` empties the baseline, the gate reads that empty baseline and saves a falsely clean report — use `php <VALIDATE> gate --save <path>` (below) instead. This rule takes precedence over a general preference for `cat`/`sed`/heredocs in file changes.

**A negative finding requires a command that succeeded.** "Searched and found nothing" and "the search did not run" print the same empty output; the shell error is one line and scrolls past. Under zsh `--include=*.php`, `*.{php,twig}`, `**/*.csv` are globbed before the tool runs — `grep -rn '…' src/Pyz/Zed/DataImport/ --include=*.php` dies with `no matches found`, exit non-zero, and reads as "no importer exists". Before writing "X does not exist": confirm exit `0` (prefer the built-in Grep/Glob tools, which cannot glob-fail); quote glob arguments in any Bash search (`--include='*.php'`); and corroborate a negative the next step depends on with a second search of a different shape (`find` vs `grep`, package listing vs source scan, Glob vs Grep).

**Before creating a project override, confirm the target path does not already exist.** Before `Write` (or any create) to a `src/<Ns>/…` path, list the target directory (Glob `src/<Ns>/…/<component>/*`) — a sibling `index.ts`/`.scss` means the override already exists and is probably committed with project logic in it (a generated template written over an existing override shows as ` M` in `git status`, not `??`). Prefer `Edit` on the existing file so the harness's read-before-write guard applies; a heredoc bypasses it. Recovery if it happens: `git checkout HEAD -- <file>`, then merge.

**Staging is the person's decision.** Leave changes unstaged and list the changed files in the report; run `git add <path>` only when the person asks. `.ai-dev/` and the plugin-installed `.claude/` subtrees belong in the developer's ignore rules, not in a commit.

**Destructive-operation policy — the one copy; every other skill points here.** `csv filter`/`delete --in-place` and header-only truncation rewrite/empty files *without* prompting on their own, and `docker/sdk reset`/`clean-data` can wipe DB + search volumes (git does not restore those). So:
- **Always preview and announce.** Before any in-place data removal/truncation or any DB/volume drop, **preview it** (`filter`/`delete` with no `--out`/`--in-place` reports `matchedRows` without writing) and tell the person in one plain line what will be removed — even when the allowlist would let it through silently. Never run a destructive step unannounced.
- **Ask only when real data is at stake that git cannot restore** — a DB/volume drop on a project that already carries real data, or files outside git — **and the confirmed answer set did not already decide it.** Questions where nothing can be lost make approvals routine, so the question is reserved for this case.
- **Everything else proceeds after the announcement:** file edits git can restore; first setup (`boot-and-verify` not yet `done`) and demo clones, whose DB holds only demo data the next boot re-creates; a removal the confirmed answer set already decided (`answers_confirmed_at` — e.g. a demo's `sample_products`, D4 `data.existing_data`, `data.mode: clean`) — log it and go; and trusted rebuilds (`standing_approval: { scope: rebuilds }`, in the person's own words).
Before a rebuild on a project with real data, ask once; a deletion git cannot restore stays in place and goes on the list for the person. (`reset`/`clean-data` weight + the hand-to-developer escape hatch: `boot-and-verify` §3b.)

# csv.php — CSV operations

Inspection (add `--plain` for line output — no JSON to parse):
- `read <file> [--limit N]` — dump header + rows as JSON. **Takes one file** — passing several is a clean error (no silent truncation to the first; use `columns`/`count` for many-file inspection).
- `count <file> [<file2> …] [--plain]` — **data-row count per file, many files in one call.** `--plain` → `rowCount⇥file` per line. Use this for "how many rows across these N files" — **never a shell `for … do … done` loop with `| grep rowCount`**; one `count` call replaces the whole loop.
- `columns <file> [<file2> …] [--plain]` — header + row count. **Accepts many files in one call** (per-file output; a missing file is reported inline, batch survives). `--plain` → column names per line, with a `== <file> ==` delimiter when multiple.
- `distinct <file>… --column C [--plain]` — distinct values of a column with row counts, sorted by count desc (`--plain` → `count⇥value` per line); takes **many files** in one call (aggregated). **Use this to inspect data — never `awk`/`sort`/`uniq -c`** (they corrupt multi-line quoted fields).

Files are positional and come before the flags (`columns <file> --plain`, not `columns --plain <file>`). `columns`/`count`/`distinct` report a specific `no input file given` error for the flags-first shape instead of the generic usage dump — read the error text, which names the argument order as the problem.

Mutation — write with **`--out <file>` for one file, or `--in-place` for one-or-many files**. **Batch: list several files before the flags and add `--in-place` to apply the same op to all in a single command** (per-file report in `files[]`) — this is how you avoid a shell `for` loop. Multiple files without `--in-place` is an error.
- `filter <file>... (--where col=val … [--match exact|prefix|contains] | --in col=v1,v2,… | --in-file col=path) [--out f | --in-place]` — keep matching rows. `--where` repeatable (AND); `--in`/`--in-file` = set-membership. Without a target it previews: `matchedRows`/`resultRows` are the full counts, the echoed `rows` are capped at 20 (`--limit N` to raise) — the counts are the destructive-gate evidence, not the row dump.
- `delete <file>... (same conditions) [--out f | --in-place]` — drop matching rows.
- `duplicate-columns <file>... --from en_US --to fr_CA[,de_DE,…] [--skip-base url] (--out f | --in-place)` — for every `X.en_US` column, add `X.<to>` copying the value; `--skip-base` leaves families alone. **`--to` takes a comma-list → all project locales in one call.**
- `duplicate-rows <file>... --column locale --from en_US --to fr_CA[,uk_UA,…] (--out f | --in-place)` — clone rows per `--to` value (glossary → all locales; store-relation rows → all stores).
- `set <file>... --column store --value US [--where col=val ...] (--out f | --in-place)` — set a column on matching rows (empty `--where` = all rows).
- `replace <file>... --column url.fr_CA --search /en/ --with /fr/ [--regex] [--where col=val] (--out f | --in-place)` — string/regex replace within an existing column.
- `scale <file>... --column value_gross [--column value_net] (--by 1.47 | --rates PLN=4.3,UAH=45 [--currency-column currency]) [--no-round] [--json-keys net_price,gross_price] [--where col=val] (--out f | --in-place)` — multiply numeric values (currency conversion); **`--column` is repeatable — net + gross scale together in one call** (`--column value_net --column value_gross`); `--rates` applies a per-currency factor in one call; `--json-keys` scales embedded price tiers.
- `derive <file>... --target value_gross --source value_net --factor 1.19 [--no-round] [--only-empty] [--where col=val] [--out f | --in-place]` — cross-column arithmetic `scale` can't do: writes `target = source × factor`, creating the target column if absent. Skips rows whose source is empty/non-numeric; a non-numeric/zero `--factor` is a hard error (never silently zeroes a column). `--only-empty` gap-fills (won't overwrite existing target values). E.g. fill gross from net + tax, or a base-currency price into a second column before converting.
- `select <file> --columns a,b,c --out file` — project columns (single file, keep-list).
- `drop-columns <file>... (--column name | --suffix .de_DE)... [--out f | --in-place]` — remove columns; `--suffix` drops a whole family across files. Repeatable; a named column absent from a file is reported (per-file `skippedColumns`), not fatal; idempotent.
- `rename-columns <file>... --rename old:new [--rename old2:new2 …] [--out f | --in-place]` — rename header columns and the matching row keys, many files in one call (repeatable `--rename` = multiple pairs). A pair whose `old` is absent, or whose `new` already exists as a different column, is reported in `skippedColumns` (not fatal); idempotent; malformed `--rename` (no `:`) is a hard error. Use it instead of hand-authoring a near-duplicate file that differs only by column names — e.g. deriving `price_product_offer` from `product_price`: `replace` the values, `rename-columns` the ref column, done in two commands with no loop.
- `apply-translations <file>... --target-column name.uk_UA [--source-column name.en_US] --map map.csv (--out f | --in-place)` — apply a `source→target` value map to one column (map file has `source,target`). **Only the target column changes** — safe by construction. Exact match, multi-line-safe; unmapped values left as-is.
- `append <file> --from <rows.csv> [--dedupe-on <col>] (--out f | --in-place)` — **the row-adding op for authoring passes.** Appends every row of `rows.csv`, whose header must be a subset of the target's (columns the rows file lacks are written empty; a column the target lacks is a hard error); `--dedupe-on <col>` skips rows whose key already exists in the target. Writes LF, atomic. This is how new glossary keys, labels or store rows go into the one file per entity — never a second `<entity>_project.csv` source (the gate's `duplicateEntitySources` forbids it) and never a hand-rolled writer (Python's `csv` defaults to CRLF; `preflight` `lineEndings` flags it).
- `add-row <file> --set col=value [--set col2=value …] (--out f | --in-place)` — append one row: repeatable `--set`, an unknown column is a hard error, unset columns are empty. Same LF/atomic guarantees as `append`. For more than a handful of rows, build a `rows.csv` and `append` it.

Notes: all access is **by header name**, never index. A missing column returns a clean JSON error with exit `2`. Idempotent where sensible. Writes are **atomic** (temp file + rename — a crash mid-batch never leaves a truncated CSV) and **LF-terminated** (the repo is LF; `git add`'s `CRLF will be replaced by LF` warning means a file was written by something other than these tools). macOS/OrbStack bind-mounts lag — re-check a written file a beat later. **Counting: never `| grep -c`** — use `rowCount` (`columns`/`read`) or `matchedRows` (`filter` preview). **Batch, don't loop.**

# validate.php — pre-boot checks

Output: JSON `{status, check, findingCount, findings, errors}`, exit `0` clean, `1` warnings only (a warning-only check such as `sku-coverage`, or `gate` with warnings and no gating finding), `2` on a gating finding. Add `--quiet` to branch on the exit code alone. **Run `php <path>/validate.php` with no arguments first** — it lists every check; the prose names only a subset of them.

- **`gate [<import-config.yml> …] [--locales a,b] [--base dir] [--baseline <gate-or-preflight.json>] [--root dir]… [--strict] [--save <path>] [--quiet]` — the close-out command: one call, one verdict.** Runs `paths` + `preflight` + `manifest-refs` + `threshold-glossary` + `duplicate-keys` + `cms-block-store` (gating), `orphan-files` (gates only with `--strict`), and six warning-only checks over the active manifests and returns `{status, gatingCount, warningCount, summary[], checks{…}}`; exit `0` clean, `2` any gating finding, `1` warnings only. **`--save <path>` writes the report itself after running** and refuses when `baselineSafe` is false — this is how the baseline is captured (`php <VALIDATE> gate --save .ai-dev/gate-baseline.json`), never `gate > file`: the shell truncates the target before the gate runs, the gate reads its own empty baseline, and saves a falsely clean report. **Everything is auto-discovered when omitted:** the manifests (`data/import/local/full_<REGION>.yml` for every region `deploy.dev.yml` boots, plus every literal `data:import --config=<path>` in `config/install/docker.yml` — the vendor payment configs), the project locales (from the `locale-store` sources), the declared stores (from the `store` source — passed to every manifest so a vendor config naming a removed store is caught), and the baseline (`.ai-dev/gate-baseline.json`, else `.ai-dev/preflight-baseline.json`). `orphan-files` gates only under `--strict` (a fresh, un-consolidated demoshop legitimately carries files no manifest imports); use `--strict` for the project-data consolidation close-out and for `done`. **A saved gate report is the baseline of choice** — capture it on the untouched clone with `gate --save .ai-dev/gate-baseline.json`, and only new findings gate across every gating check (the shipped demoshop is not clean on `manifest-refs`/`threshold-glossary` either, which a preflight-only baseline cannot suppress). **Run this gate yourself before any `docker/sdk reset|clean-data|up|console data:import`** and stop on a gating finding. With a baseline on file, only gating findings the baseline does not hold count; with no baseline, any gating finding stops the rebuild verbs, and `data:import` proceeds (capture the baseline on the untouched clone). For the rebuild verbs (`reset`/`clean-data`/`up`), trusted rebuilds (a demo clone, first setup, or a recorded `standing_approval: { scope: rebuilds }`) run after a one-line announcement, a project with real data gets one question, and before the third and every later rebuild the decision log gets `rebuild #N: <why rung 1 cannot show it>`; the step report states the rebuild count. `console data:import` needs no question: it is rung 1 of the ladder and stays cheap. Vendor-owned sources (`vendor/**`) are exempt from the project-data groups and checked for store references only; a vendor source absent on an un-booted clone (no `vendor/` yet) is not a finding.

- **`preflight <import-config.yml> [--base dir]` — the manifest-wide invariant sweep `gate` runs for you (call it directly to drill into one manifest); one driver that auto-discovers and checks the boot-critical invariants across every file the manifest imports, so you never enumerate files by hand.** Reads the manifest's `source:` list and, by column shape, bundles four checks: **url.\<locale\> global uniqueness — cross-file, like the real `spy_url` constraint** (a product URL colliding with a category/merchant URL is caught; one dup aborts the 30–60 min install; **navigation-node sources are exempt** — a nav node's url is a link *target*, legitimately repeated across menus), **is_searchable.\<locale\> non-blank** (blank = silently unsearchable), **price completeness — gross-mode aware** (a missing/`0` `value_gross`, or a missing net in a net-only file, is a hard problem; a missing net *beside a present gross* is how the shipped gross-mode stores legitimately look → reported under non-gating `priceNetWarnings`/`warningCount`), and **base-before-relation import order** (`currency` before `currency-store`, `store` before every `*-store`, **and every store-definition entry — checked on its last occurrence — before the first product/category entity**; a 3rd store's `locale-store` appended after the catalog = a silently empty store). Also flags any manifest `source:` that doesn't exist. **`--baseline <previous-preflight.json>` suppresses findings already present in that report** — capture a baseline on the untouched clone first, then only new findings gate (the shipped demoshop carries pre-existing quirks that are not yours to fix). It also runs **generate-mode required-shape checks** (`shapeWarnings`): `product-abstract` source has a `color_code` column (else 0 rows import silently), `visibility ∈ {PDP,PLP,Cart,∅}`, `product-abstract` imported with an `*approval-status` entity (else 0 search docs, invisibly), `merchant-product-offer` accompanied by `merchant-product`, and `tax_set_name ⊆` the tax source. Returns one grouped verdict (`problemCount`, then `unreadableSources`/`urlDuplicates`/`searchableBlanks`/`priceMissing`/`foreignLocaleColumns`/`foreignLocaleRows`/`shapeWarnings`/`orderViolations`), exit `2` if any. **Plus these invariant groups** (each imports without an error and surfaces only later; all gating, all baseline-suppressible): `headerOnlySources` (a source with 0 data rows — the delete-vs-empty decision was never made), `glossaryMultiLocale` (a `glossary` source carrying more than one `locale` — glossary is one file per locale), `duplicateEntitySources` (one `data_entity` from several sources in the same directory not distinguished by a store/locale token — the `<entity>.csv` + `<entity>_extra.csv` split), `storeDirMismatch` (a source under a `<STORE>/` dir whose `store`/`store_name`/`included_store_names` name another store — the `cp -r` seeding leftover that boots a silently half-empty store), `undeclaredStore` (a store value not in the `store` source — a vendor config hardcoding a removed store aborts the reset after the project import reported Successful), `searchAttributeOverlap` (a key in both `product_search_attribute_map` and `product_search_attribute` — every facet count exactly doubled), `categoryTemplateUnknown` (`category.csv` `template_name` not in the category-template source — every category then fails, then every abstract, three importers later, aborting the install), `rootCategoryNotInMenu` (a root category with `is_in_menu` ≠ 1 — the category tree publishes `[]`), `approvalStatusMissing` (an abstract SKU with no approval-status row — the publisher writes nothing, silently), `priceNonInteger` (`value_gross`/`value_net`/`value_cost`/`amount`/`threshold` not an integer — Spryker money is minor units; a decimal renders 100x wrong), `embeddedPathsMissing` (a path inside a CSV cell — workflow XML, file assets — that does not exist; **relative** paths such as `file.csv`'s `common/common/files/X.pdf` are resolved against the base dir, `data/import/` and the CSV's own directory, so a relative asset reference is checked, never skipped), `lineEndings` (a manifest CSV containing CRLF — Python's `csv` writer default; the repo is LF and git flags it only at `add` time), `discountShipmentByName` (a discount `decision_rule_query_string`/`collector_query_string` clause `shipment-method`/`shipment-carrier` with a non-numeric value — both rules compare the numeric id, so `shipment-method = 'DHL Standard'` imports and never applies), `categoryStoreIncomplete` (a store whose `category_store` rows name some child categories but not others — `category-store` spreads the root's stores to children only when the root relation is first created, so a category added on a later import gets no store row and its page shows 0 products; state every category per store, included, excluded, or both lists empty = take the parent's stores). Shipment-price files are exempt from the empty-or-`0` price rule (free shipment is a real value). **Add `--locales <pl_PL,uk_UA,en_US>` to also flag any `.<locale>` column or `locale` row value that isn't in the project's set** — the "a finished project carries only its own locales" check, across `data/import/**` (the `absent` sweep misses that tree). One exemption: `en_US` rows in a `glossary` source are never foreign — the en_US glossary is the translator fallback layer every project imports (`project-data` adapt step 1), whichever locales the stores serve. Use the individual checks below to drill into a specific file; `preflight` is the sweep that replaces remembering to run each one everywhere.
- **`manifest-diff <reference.yml> <new.yml> [--base dir]` — diff the `data_entity` lists of two import manifests.** Reports `missing` (entities the reference/demo manifest imports that the new one does not — each with its source **row count** so you can rank: rows ≈ product population → structural/required, rows ≪ → opt-in demo garnish) and `added`. Exit `2` if anything is missing. This is the mechanical guard against generate-mode silently dropping behavioural plumbing (e.g. `product-shipment-type`) — diff, then classify every omission as intentional-content-drop or must-keep-structural.
- **`known-set [<manifest>] [--base dir] [--map <entity-map.yml>] [--skills <dir>] [--emit-map [--out <path>]]` — the maintainability gate: keep `data/entity-map.yml` honest against the shipped manifest, and keep record counts out of the skills.** Defaults resolve relative to the script, so it runs from any cwd (default manifest `data/import/local/full_EU.yml`, default map `data/entity-map.yml`, default skills dir the plugin's `skills/`). Reports and gates (exit `2`) on: a manifest entity **missing from the map**; a **stale** map row the manifest no longer imports; a map `source` that isn't the file the manifest imports for that entity (or is gone from disk); any `class: unclassified` row (an undecided entity **blocks the boot** by design); a `structural` row with an empty `why`; and any **bare record count** (`N rows|files|entities|products|blocks|labels|SKUs|docs|CSVs|nodes|keys|columns|attributes|categories`) in a `.md` under the skills dir (a `0`/`~0` count or a `count-ok`-marked line is exempt). `--emit-map` regenerates the map skeleton from the manifest, **preserving the class/why of entities already classified** and marking new ones `unclassified` — a demo-data bump becomes a diff review, not a retype. It does not scan prose for stray identifiers/paths — `paths` and `product-refs` own that against the real files, where a `<placeholder>`-templated doc won't false-positive.
- `refs <file>... --column C [--column C2] (--in a,b,c | --ref-file F --ref-column K) [--split ,] [--composite]` — every value in the column(s) must be in the reference set. A **missing column is a finding**, never a silent pass. `--split` handles multi-value cells. **Multi-file:** pass several files — each column is checked only against the files that have it (a heterogeneous batch where `a.csv` has `key` and `b.csv` has `attribute_key` won't false-fail), and a column absent from every file is still flagged. (`--composite` uses the first file.)
  - **`--composite`** treats the columns as one **tuple** and checks it against the ref file's `--ref-column`s (positional) — for cross-entity integrity. E.g. every `(merchant, store)` sold must exist in `merchant_store`. Plain `refs` would wrongly pass if each part exists independently.
- `required <file> --column C [--column C2]` — cells must be non-empty (e.g. `is_searchable.<locale>` — a blank imports as silently unsearchable).
- `unique <file> --column C` — no repeated values (empty cells ignored). E.g. `url.<locale>` — a duplicate fails the import.
- `absent <file-or-dir> [<path2>...] --string S [--string S2]` — none of the strings may appear (stale-literal sweep). **Directories are recursed**, so `absent config/ src/Pyz --string DE` sweeps whole trees in one call. A path resolving to nothing readable is a `CANNOT READ FILE` finding, never a silent pass. **Triage tool, not an absolute gate** — scope a hard check to files that must be zero-hit (`CodeBucketConfig.php`, `default_store.php`), classify the rest.
- `paths <import-config.yml> [--base dir]` — every `source:` in the import config resolves to an existing file.
- `product-refs <dir> (--keep-from <file>:<column> | --keep-in a,b,c)... [--pattern n1,n2] [--list-suffix _skus] [--exclude <substr>]... [--exclude-column <col>]...` — **broad orphan scanner for a catalog reduction.** Walks every CSV under `<dir>`, auto-discovers each product-ref column (name in `--pattern`, default `sku,abstract_sku,concrete_sku,product_sku,product`; **plus any header carrying `sku` as an underscore token** — `sku_concrete`, `abstract_product_sku`, `alternative_product_concrete_sku`, …; plus any column ending in `--list-suffix`, default `_skus`, treated as a comma-list), reports every token not in the kept union set (`--keep-from` file:columns ∪ `--keep-in`). The JSON carries a `columns` **coverage summary** (a 100%-orphan column is usually a non-product code, e.g. `product_option.sku`; `--exclude-column` it) and the orphan `findings`. `--exclude <substr>` skips files not in the active manifest. Exit 2 on any orphan. The coverage tool a catalog reduction needs (the reduce strategy in [[project-data]]).
- `manifest-refs <import-config.yml> [--base dir]` — **orphan sweep across the manifest's distinctive-key relations, in one command.** By column-name convention it builds each key family's producer set from the entity that defines it (`abstract_sku`←product-abstract, `concrete_sku`←product-concrete, `sku`←both, `merchant_reference`←merchant, `product_offer_reference`←product-offer/merchant-product-offer, `category_key`←category, `sales_unit_key`←product-measurement-sales-unit), then flags every consumer cell with no producer. Reports `checked` families and `unchecked` ones (producer entity absent from the manifest → not validated, never a false orphan). Exit 2 on any orphan. **`category_key` is list-valued** — the abstract importer `explode(',')`s it (`ProductAbstractWriterStep::getCategoryKeys()`), so a comma list is the shipped way to put a product in a second category; the check splits that family on `,` and reports one finding per unresolvable part, never per cell. Every other family stays single-value (splitting universally would mask real orphans in columns whose values legitimately contain a comma). **It is not the whole FK graph:** it covers only families whose column name is distinctive. Relations keyed on a **generic** column — `product-label-store`→`product-label` by `name`, `stock-address`→`stock` by `warehouse_name`, etc. — can't be represented without cross-entity false positives, so they are invisible here. **Heuristic for the gap:** any file the project **copied from a seeded demo dir whose parent set the project then replaced** (labels, sales units, warehouses, attributes) counts as unchecked until a targeted `refs --ref-file` against the project's own parent passes. Run `manifest-refs` as the cheap first net, then `refs --ref-file` per replaced-parent relation — don't treat a green `manifest-refs` as full referential integrity.
- `duplicate-keys <import-config.yml> [--base dir]` — **gating**: the same primary key written twice in one
  source. Contradicting duplicates (two different values) gate; additive and identical ones are reported.
- `cms-block-store <import-config.yml> [--base dir]` — **gating**: a CMS block visible in one store and not
  its twin, which renders as an empty slot on exactly one storefront.
- `orphan-files <import-config.yml> <root-dir> [<root2>…] [--base dir]` — **the complement of `paths`**: lists every import asset under the roots — **every file type, not only CSV** (state-machine XML, SSP PDFs; manifests, READMEs and dotfiles are skipped) — that **no** manifest source references, **counting paths embedded in CSV cells as references** (workflow.csv `definition`; `file.csv` `path`) — **absolute `data/import/…` and relative** (`common/common/files/X.pdf`, resolved against the base dir, `data/import/` and the CSV's own directory), so a referenced PDF is never declared an orphan. (A check limited to CSV files, or to absolute paths, would report the workflow XML or the SSP PDFs as orphans, and deleting them breaks the install or leaves `file.csv` dangling.) `paths` proves every source resolves to a file; `orphan-files` proves every file is a source. Reports `onDisk`/`referenced` counts + the orphan `findings`; exit 2 on any orphan. The gate the project-data "Consolidate & clean up" pass uses to prove the on-disk tree equals the active manifest.
- `threshold-glossary <import-config.yml> --locales a,b [--base dir]` — **asserts every Sales-Order-Threshold row's message key resolves in each project locale's glossary.** The regular threshold (`data_entity: sales-order-threshold`) builds its key at runtime from type+store+currency (`sales-order-threshold.<type>.<store_lc>.<cur_lc>.message`) and looks it up unconditionally — the empty `message_glossary_key` column is not an exemption. For every threshold row × locale, flags the (key, locale) pairs missing from the manifest's `glossary` sources. Reports `thresholdRows`/`thresholdFiles`/`glossaryFiles` so a `0` finding count from *no threshold file found* is visible, not falsely reassuring. Skips `merchant-relationship-sales-order-threshold` (auto-generated, never glossary-seeded). Exit 2 on any miss. Catches the green-boot-then-500-at-add-to-cart defect the boot itself won't surface (the [[project-data]] threshold gate).
- `sku-coverage <import-config.yml> [--base dir]` — **the complement of `manifest-refs`: which files is a SKU missing from?** For every SKU (`abstract_sku`/`concrete_sku`/`sku` families across the manifest's catalogue sources) it compares the set of files the SKU appears in against the modal set across all SKUs and reports the files a SKU is absent from that its peers are in (a product added mid-project absent from `merchant_product.csv` and `product_shipment_type.csv` → no "Sold by", **"No shipping types available for this product."** — both invisible to every outbound check, both visible only on screen). Runs inside `gate` as a **WARNING** (non-gating: a deliberately unassigned SKU is legitimate) — read the findings, don't wait for exit 2. **Run it after every product add**, standalone.
- `translation-coverage --from <locale> --to <locale> [<import-config.yml>|<dir>|<csv>…] [--base dir]` — **untranslated text in a translated column**: for every `<base>.<from>` column with a `<base>.<to>` twin, the rows whose two cells are identical (non-empty, at least three letters) — an English copy left in a `.<to>` column reads as translated to every other check. Not in `gate` (it needs the two locales named); run it after `duplicate-columns` and again when the translation is claimed done.
- `inventory <import-config.yml> [--base dir] [--plain]` — **the semantic read every referential check skips.** One line per manifest source: `data_entity`, source path, row count, and a sample of its free-text values (the first distinctive cells). This is the artifact the [[project-data]] consolidation pass records (in its evidence file) and classifies `project` / `generic-plumbing` / `demo-leftover` before `done` — the sample cells show, for example, another vertical's demo assets ("Example Asset A") that are still imported under a green `gate --strict`. Not a gate, by design: project-data closes on the classified inventory, not on a green gate alone.

Concept-free by design: new demoshop files/entities need no new code — point the checks at them. A green boot is still the correctness authority; these are the cheap early net. **If a tool cannot do something, a fallback is fine — but prefer the tool** (`awk`/`sed`/`python` corrupt multi-line quoted fields and prompt).

## Data & references — the maintained literals

Two files hold every demo-data literal the consumer skills rely on, so a demo-data bump is one diff here instead of a hunt across prose files. `known-set` keeps both honest.

- **`data/entity-map.yml`** — one row per shipped `data_entity`: its source **filename** (which often differs from the entity name — that mismatch is why the file exists), its **class** (`structural` = theme-independent plumbing kept regardless of catalog; `content` = theme-dependent demo data; `unclassified` = undecided, blocks boot), and, for structural rows, the **`why`**. The authoritative structural keep-set the `clean`/`minimal-baseline` keep-lists derive from.
- **`references/demo-facts.md`** — the concrete **identifiers** (a real SKU pair, the `cms-block-email--` prefix + `block_key` column, the shipped product-label + navigation keys, the `shop_ui` colour keys, the manifest families), each paired with the command that re-derives it. **No record counts** — those are stated as their measuring command, never a stored number.

# Flag cookbook (one worked example per command — copy, don't guess)

Non-obvious flag behaviours:
- **`set` adds a missing column** — `csv set url.uk_UA.csv --column url.uk_UA --value /uk/` creates `url.uk_UA` if absent (not only sets an existing one).
- **prefix/substring match uses `--match`** — `csv filter cms_block.csv --where block_key=cms-block-email-- --match prefix` (there is no `--where-contains`; note the column is `block_key`, not `name`).
- **membership uses `--in` / `--in-file`** — `csv filter product_abstract.csv --in abstract_sku=A1,A2` or `--in-file abstract_sku=keep.txt` (one value per line).
- **`refs` reference set is `--in` OR `--ref-file`+`--ref-column`** — `validate refs offer_store.csv --column store --ref-file store.csv --ref-column name` (not `--in-file`).
- **`scale` scales net+gross together** — `csv scale product_price.csv --column value_net --column value_gross --rates PLN=4.3,UAH=45 --in-place`.
- **`product-refs` takes a directory + `--keep-from <file>:<column>`** (not a manifest) — `validate product-refs data/import/common --keep-from …/product_abstract.csv:abstract_sku`.
- **`preflight` / `manifest-diff` take a manifest yml** — `validate preflight data/import/local/full_EE.yml --base . --locales en_US,pl_PL,uk_UA`; `validate manifest-diff data/import/local/full_EU.yml full_EE.yml --base .`.
- **`known-set` runs from any cwd on its defaults** — `validate known-set --base <repo-root>` (checks the map + the count gate); `validate known-set --emit-map --base <repo-root> --out <scratchpad>/skeleton.yml` to regenerate the map skeleton for a diff review after a demo-data bump (`--out` writes the file itself, like `gate --save`; without it the skeleton is printed — never a `>` redirect, and never `/tmp`: use the session scratchpad).
- **`--baseline` takes a saved gate (or preflight) report — capture it with `--save`, never a redirect** — `validate gate --save .ai-dev/gate-baseline.json` on the untouched clone (the tool writes after running and refuses when `baselineSafe` is false; `gate > file` truncates the target first, the gate reads its own empty baseline and saves a falsely clean report). Then `validate gate --baseline .ai-dev/gate-baseline.json` gates only new findings (`gate` also auto-discovers that path).
- **`append` adds rows from a file, `add-row` adds one** — `csv append glossary.en_GB.csv --from new-keys.csv --dedupe-on key --in-place` (header of `new-keys.csv` ⊆ target's; missing columns empty); `csv add-row product_label.csv --set name=project-new --set is_active=1 --in-place` (unknown column = hard error).
- **`sku-coverage` / `inventory` take a manifest yml, like `preflight`** — `validate sku-coverage data/import/local/full_EU.yml --base .` after every product add; `validate inventory data/import/local/full_EU.yml --base . --plain` → record it in the evidence file and classify every line before `done`.
- **`read` is one file; `columns`/`count`/`distinct`/`filter`/`delete`/`set`/`scale`/`drop-columns` take many** (with `--in-place` for the mutations); `append`/`add-row` take one target file.
